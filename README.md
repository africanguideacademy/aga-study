# AGA Study App (pilot)

A study and quiz web app for African Guide Academy students. It's built from AGA's own photos and call recordings.

## What's here
- `app/`: the website itself (this is the folder that gets hosted).
  - `index.html`, `styles.css`, `app.js`: the app.
  - `data.js`: content, generated by the build script. Don't edit it by hand.
  - `media/birds/`: 80 photos, resized for the web (about 6 MB in total).
  - `media/calls/`: 447 bird calls (about 185 MB).
- `data/birds.csv`, `data/calls.csv`: the content lists. These are also in the Google Sheet
  "AGA Study App - Bird Content":
  https://docs.google.com/spreadsheets/d/1BiZlShG4BIlv0FbYUbMxfxn-BUoUC7H96SzIb_Mp0yg
- `tools/build-data.js`: scans the Y:\ photo and call folders, matches photos to calls, and writes the CSVs and `app/data.js`.
  Spelling fixes and name corrections are kept in `PHOTO_FIXES` and `CALL_FIXES` at the top of this file.
- `tools/copy-media.ps1`: resizes the photos and copies the calls into `app/media`.
- `tools/serve.js`: a local test server.

## Study modes
- Name the bird (from a photo)
- Whose call is this? (from a sound)
- Match call to photo
- Find the bird (from a name)
- Flashcards
- Browse

## Offline / install on phone
- The "Use offline & install" page explains how to install the app on a phone. On Android, Chrome shows an Install button; on iPhone, the page gives Safari's Share â†’ Add to Home Screen steps.
- The service worker (`app/sw.js`) saves the app files and all photos (about 6 MB) the first time the app opens.
- Calls are only saved when the student taps Download: FGASA 80 calls (21 MB) or the full library (185 MB).
- With no signal, quizzes only use calls that have been downloaded.
- Updates still reach students: when they're online, the app always fetches the latest app files.
- The logo and icons are made by `tools/make-icons.ps1`, which uses the official AGA logo files (Koru Designs 2019, on `Z:\MULTIMEDIA\KORU DESIGNS\AFRICAN GUIDE ACADEMY\2019`).
- The colours are AGA's house colours: maroon #6e1e10, dark brown #3d0f07, ochre #c06a1a, and cream #f4f1ec.

## Audio (calls)
- `tools/encode-audio.ps1` re-encodes every call to a small mono MP3 (56 kbps, 32 kHz) with no album art. This makes calls 2-3 times smaller, so they load much faster on phones.
- It also cuts the spoken introduction (common name and scientific name) from the frog CD tracks, using `data/frog-trim.json`. `tools/find-voice-intro.ps1` creates that file by detecting the pauses.
- Needs FFmpeg: `winget install Gyan.FFmpeg.Essentials`.
- When calls are added, run in order:
  1. `tools/copy-media.ps1`
  2. `tools/encode-audio.ps1`
  3. `node tools/build-data.js`
- The bird presentations are turned into data by `tools/extract-pptx.ps1`. The originals it uses are kept in `data/originals/`, which is not committed.

## Student progress submission
- On the "Submit progress" page, students enter their first name, surname and Omang/passport number once; the phone remembers them. They then tap Submit progress.
- The results go to an Apps Script web app in `progress-script/`, deployed with clasp from the account africanguideacademy@gmail.com.
  - Script: https://script.google.com/d/18-cnth_X1BqTck4al6HUTA3ZRy1v9U9LwJc6uBPtHgt_QQ70CPfuEBL5/edit
  - The script writes to the spreadsheet **"AGA Study App - Student Progress"**.
    - The **Submissions** tab keeps every submission.
    - The **Students** tab keeps the latest totals, one row per student.
  - It looks up each student's Student ID in the AGA Student Profiles registry by matching the Omang/passport number. It only reads the registry and never sends anything from it back.
- If there's no signal, the submission waits on the phone and is sent automatically later.
- To update the script: `cd progress-script; clasp push; clasp deploy -i <deploymentId>`. Keeping the same deployment ID keeps the same URL, which is set as `PROGRESS_URL` in `app/app.js`.

## Manual questions
- These are multiple-choice questions written from the *Botswana Guide Training Manual* (7th ed., June 2025). The Birds chapter (p92-107) is done first, with 108 questions.
- The master copy is the **Questions** tab of the Google Sheet. Each row has: question, correct answer, 3 wrong answers, explanation, manual page, and a Status of Draft, Approved or Rejected.
- Only **Approved** questions appear in the public app.
  - **Draft** questions can be previewed at `https://africanguideacademy.github.io/aga-study/?preview`. Nothing in the app links to this address, but anyone who has it can open it.
- **Current state (16 Nov 2026):** at Bernard's request, the Birds Draft questions are live in the public app for testing, each with a "Draft" label.
  - To keep them live, build with `$env:DRAFTS_LIVE='1'; node tools/build-data.js`.
  - Once Grant has reviewed them, build without that setting so only Approved questions are live.
- Text in the manual's green boxes isn't examinable, so it's left out.
- To publish after reviewing:
  1. Export the Questions tab to `data/questions.csv`.
  2. Run `node tools/build-data.js`.
  3. Run `tools/publish.ps1`.

  Or simply ask Claude to "publish approved questions".
- `tools/seed-questions-birds.js` created the first Birds draft. It's kept for reference only; don't run it again, because it would overwrite `data/questions.csv`.

## Species fact cards

Tap a photo in **Browse** to open the species page. It shows the photo, the call, "Did you know?", size, where it lives, food and breeding.

- Master copy: the Google Sheet's **Species Info** tab. Locally it's `data/species-info.csv`. The app matches rows by the species **Name** exactly as it appears in the app.
- New drafts go in `data/species-info/<group>-*.json`. Run `node tools/add-species-info.js` to append them as Draft. It skips names that are already there, so it never overwrites Grant's edits.
- Status works the same way as for questions: only Approved cards are public, unless the app is built with `DRAFTS_LIVE=1`, in which case Draft cards show with a Draft label.
- To sync Grant's edits: read the tab into `data/species-info.csv`, then run build-data and publish.

## Species photos (mammals, reptiles, frogs, arthropods, plants)

- **Species lists:** `data/species-lists/<group>.json`, one entry per species: name, scientific name, group, and whether it's in the manual (with page). Each list starts with the manual's species, then adds common Botswana species.
- **Getting photos:** `node tools/fetch-photos.js [group]` downloads one free-licence photo per species from iNaturalist.
  - Only CC0, CC BY and CC BY-SA photos are used.
  - Research-grade observations from Botswana are tried first, then the rest of Africa.
  - Photos are saved to `app/media/<group>/`, with the credits in `data/photos/<group>.json`.
  - It only fetches species that have no photo yet, so it's safe to rerun after adding names.
  - To get a different photo for one species: `node tools/fetch-photos.js mammals --redo "Impala"`.
- **Credits:** each photo's credit shows on its species page, and all credits are listed on `#/credits` (linked in the footer). The licences require this.
- **Student photos:**
  - The **Send a photo** button on a species page, or **Share a photo** in the footer, uploads a photo. The phone shrinks it to 1600 px first.
  - The upload goes to the Apps Script. It saves the file in the Drive folder "AGA Pocket Guide - Photo Submissions" and adds a row to the **Photos** tab of the Student Progress sheet with Status = Pending.
  - A trainer sets Status to **Approved** or **Rejected**.
  - `node tools/sync-photos.js` pulls the approved photos into `app/media/user/` and records them in `data/photo-overrides.json`. They then replace that species' photo in every list, credited "Name Surname (AGA)". Rebuild and publish afterwards.
  - Any photo can be replaced by hand the same way: add an entry to `data/photo-overrides.json`.
  - Drive access needs a one-time authorisation: run `setupPhotos` in the Apps Script editor.
